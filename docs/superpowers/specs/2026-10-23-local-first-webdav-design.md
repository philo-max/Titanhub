# Titanhub 本地优先与可选 WebDAV 同步设计

日期：2026-10-23。状态：用户已确认产品方向；本文是实施前技术设计，尚未实现或验收。
责任：Codex 负责决策、拆单与复核；Claude 负责技术设计与后续实现；agy 负责验收矩阵。

## 1. 交付范围

- 默认无需注册：收藏、观看和阅读进度保存在当前设备，重启可读取并恢复位置。
- 正常退出先等待本地写入队列确认，再关闭内置后端；不等待网盘完成。强制终止仅保证已确认保存的数据，不承诺恢复尚在内存中的修改。
- WebDAV 默认关闭，用户配置自己的网盘或 NAS 后手动同步；不需要 Titanhub 账号服务器。
- 第一版同步收藏和每部作品最近一次观看/阅读位置；完整历史时间线、插件代码、下载内容、偏好、账号及凭据不进入同步文件。
- 先完成 Windows Electron，再完成 Flutter 手机端互通。纯浏览器部署沿用原有服务端账号方式，第一版不提供浏览器直连 WebDAV。
- 离线保障指本地数据读写；首次加载网络视频、漫画图片和小说正文仍依赖来源网络可用。
- 自动同步、多人共享、跨来源内容自动归一、墓碑回收及云账号改造均不在本轮范围。

### Windows 安装交付（用户新增硬性要求）

- 正式客户端交付为 Windows x64 安装向导 `Titanhub-Setup-<version>-x64.exe`，采用现有 electron-builder 的 NSIS target。
- 支持选择安装目录、桌面与开始菜单快捷方式、系统应用列表中的卸载；默认按当前用户安装。
- 安装包包含 Electron、本地 Hono 后端、Next standalone、SQLite/WASM 和必要插件资源。用户无需安装 Node.js、PostgreSQL 或运行开发命令。
- 程序目录与资料目录分离；SQLite、WebDAV 配置与设备标识保存在稳定 userData 路径。覆盖升级、默认卸载及重装均保留用户资料。
- 保持 appId、产品名及实际资料路径稳定；自动更新不在第一版范围，先支持下载新安装包覆盖升级。
- 当前 `apps/desktop/package.json` 仅支持 dir/portable；现有 Windows CI 构建 Flutter ZIP，尚未满足本要求。保留内部 dir 产物供烟测，增加独立 Electron 安装包流水线。
- 安装包构建与干净环境启动验证前期打通，正式交付前再次验证安装、升级、卸载与本地功能，不能只验开发模式。

## 3. 本地会话：无需注册且保持访问保护

推荐使用每次启动随机生成的本地能力令牌，避免先建设用户表或依赖后端 IPC 签发 JWT。

1. Electron 主进程用系统随机源生成至少 32 字节令牌，只在内存持有，并通过子进程环境变量交给本地后端。
2. 后端只有在 `TITANHUB_DESKTOP=1`、绑定 `127.0.0.1` 且启动令牌有效时启用该会话；缺配置直接启动失败。仅开启 SQLite 不代表允许本地身份。
3. 桌面鉴权用恒定时间比较当前本地令牌，成功后得到固定本地主体 `local`；无令牌、错误令牌及云端 JWT 均返回 401。非桌面部署保留原有 JWT 行为。
4. 主进程注册 `session:local`，校验发送者是当前应用窗口、主 frame、当前真实 webUrl；preload 仅暴露 getLocalSession。
5. 页面只在内存保存本地令牌，通过 Authorization 发往 preload 提供的后端地址。不得从查询参数或缓存重定向带令牌请求。
6. 签名密钥、WebDAV 密码不交给页面；本地令牌不进入 URL、命令行参数、localStorage、日志、同步数据或持久化 authStore。
7. 会话初始化成功后才能加载本地收藏与进度。失败提供重试，不把空结果当成加载成功。
8. 本地模式与云账号状态分开，桌面菜单展示“本地资料”；浏览器登录行为保持原样。旧 user_id 数据保留，不自动复制到 local 身份下。
9. 复用 Electron 单实例锁，失锁后立即终止启动；同一资料目录只支持一个写入进程。独立测试实例必须用不同资料目录和 deviceId。
10. 主进程交付 apiBase 前核对后端启动结果与实际监听地址，并用一次性随机挑战的 HMAC 证明对端持有本次启动能力；不能仅凭公开 health 返回 200 就发送令牌。
11. 外部浏览器等非会话子进程不得继承本地能力或 WebDAV 凭据。保留现有公共媒体读取行为，不给 img/video URL 添加令牌；私有收藏和进度继续鉴权。

令牌保护本地 HTTP 接口；它不承诺阻止同一操作系统用户下的恶意软件或已攻陷的应用页面。

## 4. 数据模型与合并规则

- 协议版本 `schemaVersion=1`；每台安装独立生成稳定 UUID `deviceId`，只保存在本机，不从另一设备备份导入。
- 媒体 key 定义为 JSON 编码数组 `[mediaType, pluginId, mediaId]`，避免字符串分隔符歧义。三个分量必须为字符串，不做 Unicode 归一化；原始字段仍显式保存并验证一致性。
- 收藏记录与进度记录分别带版本；收藏使用 `isDeleted` 墓碑。第一版不自动丢弃墓碑。
- 进度包括 chapterId、chapterNo、status、ratio，以及类型对应的定位：视频秒数、漫画零基 pageIndex、小说正文滚动比例。不存在的章节不按章节序号猜测跳转。
- 标题和封面 URL 可作为显示元数据，不承载凭据；缺少元数据仍能保存和显示条目。
- 版本为 `{counter, deviceId}`，按计数再按 deviceId 的 UTF-8 字节序比较。计数为非负安全整数，接近上限拒绝写入并提示，不允许溢出。
- 每次本地编辑使用 `max(本机计数, 已接受远端的最大计数)+1`；记录与计数在同一事务中保存。导入远端不为它重新生成版本。
- 逐 key、逐记录类别选择最大版本的完整记录；同版本不同内容视为协议损坏并停止。比较验证后的规范字段结构，数值按值比较，不比较 JSON 空格或键顺序。合并必须满足交换律、结合律和幂等。
- 墙钟时间只供显示，不决定冲突。真正离线并发编辑由确定性版本排序决胜，不能承诺真实时间上最后一次编辑获胜。
- 不取最大播放进度：同步后主动从头重看的新编辑能够覆盖旧进度。收藏删除也不能仅靠“文件里没有该条目”表达。
- 相同来源、相同媒体的多章节进度第一版只保留最近一次有效编辑的章节；跨来源切换不自动折算进度。

桌面业务表仍沿用 SQLite；增加同步状态/版本元数据，业务修改与元数据更新同一事务。手机用相同线格式写入 Drift，不传输数据库文件。

## 5. WebDAV 方案选择

| 方案 | 优点 | 代价 | 决策 |
| --- | --- | --- | --- |
| 单一共享快照 + 强 ETag 条件写 | 文件少 | 依赖服务端可靠执行 If-Match，需处理条件写重试 | 暂不采用 |
| 每设备独立快照 + 确定性合并 | 设备互不覆盖，避免共享写入点 | 需列目录、版本发布及有限清理 | 推荐 |
| 全量数据库备份恢复 | 实现直观 | 桌面和手机结构不同，无法实现记录级合并 | 仅适合作为未来独立备份功能 |

拟定远端路径：`<用户指定根目录>/Titanhub/sync/v1/devices/<deviceId>/<generation>.json`。
generation 是本机持久化的单调发布序号，与记录 counter 分开；文件名补零到 20 位并按安全整数解析比较，不会因一次失败而重新使用不同内容。

### 发布与读取

1. “测试连接”验证配置目录的列举、建立子目录、读写及 MOVE 能力；测试只用专用随机文件，清理失败明确提示。
2. 手动同步列举所有设备，完整读取每设备最高已提交 generation；忽略 `.tmp`，但最高 `.json` 损坏不得回退旧世代。GET 遇到清理导致的 404 时重新列举一次，仍失败则停止。
3. 先完整验证版本、字段类型、大小和条目上限，再合并。坏 JSON、未知协议或读取失败整次停止，不写本地合并结果，不上传，不清理远端。
4. 在本地事务中合并刚读取的远端与此刻的最新本地状态，更新计数并预留 generation，持久化待上传的准确快照。
5. PUT 到本设备唯一 `.tmp`，再 MOVE 到唯一最终世代名，禁止覆盖已提交文件；GET 验证已提交内容与待上传内容一致后才记录上传成功。
6. 上传中本地新修改保留较新版本并标记待同步；已上传快照的成功不能清除它们。一次只运行一个同步任务。
7. 上传或 MOVE 超时先 GET 核对最终文件：与持久化的待上传字节完全相同可确认成功；404 时先核对临时文件再重试同一发布；内容不同报冲突，不覆盖。崩溃恢复复用已持久化的准确字节。
8. 仅在新世代验证成功后清理本设备较旧世代及无活跃任务引用的遗留临时文件，至少保留最近两份提交；清理失败是警告，不删除其他设备文件或有效墓碑。
9. 首次启用同样先读取合并，空设备不会清空远端。其他设备并发提交可能本轮不可见，停止编辑后需重复成功同步直至各端收敛。

第一版要求 PROPFIND、MKCOL、GET、PUT、MOVE；清理需要 DELETE。服务不支持关键能力时明确报告不兼容，不静默改成覆盖共享文件。
世代发布避免主动覆盖已提交文件，但具体服务的可见性、MOVE 和一致性仍须测试，不能未经实测宣称原子性。
损坏文件错误须标出设备和路径，保留上一提交供人工恢复；第一版不自动排除设备。坏设备可能阻塞同步，但本地使用不受影响。

## 6. 凭据、请求出口与用户反馈

- Windows 主进程使用当前 Electron 版本支持的 safeStorage API 加密存入 userData；先检查实际可用性，失败不降级为明文持久化。
- Linux 若未来支持，须额外排除 basic_text 后端；不把 isEncryptionAvailable 单一检查视为充分保护。不要为本功能顺带升级 Electron。
- 页面可以提交初次配置，但读取配置只返回地址、用户名及“已保存密码”状态，不返回密码。测试连接和同步入口只接受已保存配置，不提供任意 URL 代理。
- 后端执行 SQLite 合并和 WebDAV 请求，主进程通过受控 IPC 交付凭据并接收结果；P1 开工前先验证开发与打包运行时的双向 IPC。
- WebDAV URL 默认 HTTPS；局域网 HTTP 需要用户明确选择。请求仅限配置服务器及指定根目录；拒绝携带 URL userinfo、越界路径和跨来源重定向携带 Authorization。
- 限制响应大小、XML实体处理、并发与请求超时；错误日志必须移除 URL 凭据和认证头。401/403、只读、配额不足、网络失败分别给出可操作提示。
- Flutter 由原生进程发起 WebDAV 请求，安全存储依赖在 P2 选型并实测，不假定当前 pubspec 已有相关能力。
- 状态区分：未启用、未同步、同步中、成功、有待同步更改、失败；同时展示最近成功时间与可重试错误。只有远端提交验证通过才显示本轮成功。
- 关闭 WebDAV 停止后续远端操作，保留本地数据与待同步状态；不删除网盘文件。

## 7. 分期与验收边界

| 阶段 | 交付 | 验收门槛 |
| --- | --- | --- |
| P0-A | 桌面本地能力会话 | 免注册能受保护地读写本地主体，云端不接受该能力 |
| P0-B | 本地存储、复合标识及入口 | 无网络收藏增删、重启恢复、同 ID 不同来源隔离；迁移保留旧行 |
| P0-C | 视频/漫画/小说位置恢复 | 数据加载完成后恢复，初始化不写入零进度覆盖旧记录 |
| P-PACK | Windows NSIS 安装与升级 | 干净系统安装启动、快捷方式、保留资料的覆盖升级及卸载重装；与 P0 分开限定文件并尽早打通 |
| P1-A | 版本化快照和合并 | TS 纯函数与存储事务测试，黄金向量固定协议语义 |
| P1-B | 桌面手动 WebDAV | 测试连接、受保护凭据、首次合并、失败重试、双实例收敛 |
| P2 | 手机本地对齐与 WebDAV | Dart 跑同一组黄金向量，再做桌面手机真实互通 |

既有大量未提交改动必须保留。实施按工单限定文件，小步验证；本轮没有执行这些工单。
服务商兼容性不阻塞 P0；发布宣称支持某服务前必须有专用测试目录的实际证据。尚无指定服务商或账号。
